# ULR Companion

UNLIGHT:Revive 自訂 COST 規則與對戰追蹤的執行端。

依《ULR Cost Rules Integration Plan Spec v0.3》建置。三方分工：

| 元件              | 負責                                           | 在哪                  |
| ----------------- | ---------------------------------------------- | --------------------- |
| **ULGG**          | 公開規則登錄、版本治理、Room 驗證、戰果統計    | <https://ulgg.online> |
| **GitHub**        | 原始碼、Schema、版本契約、CI、Release          | 這個 repo             |
| **ULR Companion** | 規則計算、CDP 觀測、遊戲內顯示、回報與自動更新 | 這個 repo             |

---

## 開始

需要 Node.js 20.11 以上。

```bash
git clone https://github.com/UnlightPlugin/ulr-companion.git
cd ulr-companion
npm install
npm run verify      # format + lint + typecheck + test
```

`npm run verify` 全綠就代表環境沒問題，可以開始接工作包了。

試跑一份規則：

```bash
npx tsx apps/companion/src/index.ts packages/rule-schema/test-vectors/rules/arcadia-balance-1.2.0.json
```

### 移動階段仲裁（WP-15）

托盤程式，一份管一個遊戲客戶端。

```powershell
npm run tray                      # 上次用的那份配置
npm run tray -- --profile <id>    # 指定配置
npm run tray -- --port 9333       # 相容用法：對得上就用那份，對不上開臨時的
```

⚠ **中間人預設是雲端的那一台**（見下面「這個插件會連到哪裡」）。要在同一台
電腦上讓兩份插件互相握手（雙開測試），把配置裡的「中間人」填 `local` ——
那時先開的那份會自動當 broker，不必再多開一個視窗。

**打包成安裝檔：**

```powershell
npm run dist        # → out/release/ULR Companion Setup 0.1.0.exe
```

NSIS、`oneClick`、`perMachine: false`（裝到 `%LOCALAPPDATA%`，更新不需要 UAC ——
裝到 `Program Files` 的話**每次更新都會跳 UAC**，玩家會以為中毒）。
圖示是程式現畫的漩渦，repo 裡沒有 `.ico`。

安裝檔 **82 MB**，解壓後 284 MB。這個大小幾乎全部是 Electron 自己：

|                            | 大小       |
| -------------------------- | ---------- |
| 我們的程式碼（`app.asar`） | **0.4 MB** |
| Chromium 主程式            | 200 MB     |
| GPU／著色器 DLL            | 42 MB      |
| ICU、授權條款、資源 pak    | 38 MB      |
| locale pak（5 種語言）     | 2.9 MB     |

已經做掉的：**locale 從 55 種砍到 5 種**（44 MB → 2.9 MB）、sourcemap 不進包、
`compression: maximum`。再往下就只剩 GPU 相關的 DLL，而砍掉它們的風險是
「某些機器上畫面靜靜地不出來」—— 對一個要在對戰中一直開著的工具不值得。

⚠ **Electron 的下限大約就是 70 MB**。真要做到 5–10 MB 得換成 Tauri／WebView2，
而那表示主程序要用 Rust 重寫 —— CDP adapter、仲裁引擎、中間人全部是 TypeScript，
不成比例。

⚠ **還沒有程式碼簽章**，首次安裝會跳 Windows SmartScreen「不明的發行者」。
後續更新不會再跳（安裝器由已安裝的程式啟動，不帶 Mark-of-the-Web）。
下載頁要老實揭露這件事並附安裝檔的 SHA-256，**不要教玩家關掉系統防護**（§10.3）。

⚠ **從 VS Code 的終端機啟動打包版會失敗**，錯訊是 `bad option: --port`。
那是 `ELECTRON_RUN_AS_NODE` —— VS Code 的 extension host 會設它，Electron 的 exe
於是被當成純 Node 跑。開發時用 `npm run tray`（`scripts/run-tray.mjs` 會清掉它），
或從捷徑／檔案總管開。一般玩家不會遇到。

**多開是進階功能，預設關閉。** 一般玩家裝完就是一個視窗管一個遊戲客戶端，
不需要知道「配置」這回事 —— 要打開它得自己去 設置 › 關於 最底下勾「進階」，
「配置」才會出現在設置的**最後一格**（優先級最低）。

打開之後，設定 › 配置維護一張清單，按「開新實例」就再開一個視窗綁另一份 ——
埠寫在命令列的話，一般玩家永遠開不了第二個。新增時會自動避開已被佔用的埠：

| 名稱   | 客戶端 | 遊戲埠 | 狀態     | 中間人   |
| ------ | ------ | ------ | -------- | -------- |
| 主帳號 | 桌面版 | 9333   | 對戰中   | （雲端） |
| 小號   | 網頁版 | 9334   | 遊戲開著 | （雲端） |

⚠ **兩份配置不能共用同一個遊戲埠**（Windows 的目錄鎖會擋掉第二份，症狀是
「按了開新實例但什麼都沒發生」）。

「狀態」欄只說**那個埠上有沒有遊戲在回話**（主程序每四秒敲一次
`/json/version`）。**它回答不了「另一份有沒有插件在管它」** —— 那是另一個
process，這個視窗問不到。自己那一列才是引擎的真實狀態。

畫面照里程碑分成六個大分頁，各自有側邊子分頁：

| 分頁 | 子分頁                                  | 狀態                        |
| ---- | --------------------------------------- | --------------------------- |
| 戰鬥 | 準備 · 秒數上限                         | ✅ 可用                     |
| 戰鬥 | 加速                                    | 🟡 做好了，**刻意先不開放** |
| 戰鬥 | 記牌 · 牌譜                             | 🔲 前瞻預告                 |
| 牌組 | Cost 表                                 | 🔲 前瞻預告（卡在 WP-02）   |
| 渦   | 速度加倍 · 推薦隊伍 · 排名與獎勵        | 🔲 前瞻預告                 |
| 獎勵 | 未來視                                  | 🔲 前瞻預告                 |
| 任務 | 寶箱標註                                | 🔲 前瞻預告                 |
| 設置 | 配置 · 連線 · 啟動 · 更新 · 記錄 · 關於 | ✅ 可用                     |

未實作的頁不是「敬請期待」—— 每一頁都寫清楚**卡在哪**。

外觀是**純 CSS 重現**的 Unlight 風格，色票量自跑著的客戶端
（分頁 `#622b2f`／hover `#873136`、底 `#1e2336`）。系統匣圖示是程式現畫的菱形
（深紅描邊＋狀態色）。repo 裡**沒有任何遊戲圖檔**，也沒有官方美術 ——
這既是設定視窗能維持 `default-src 'none'` 的原因，也避免第三方插件看起來像官方出品。

遊戲裡的 OK 鈕預設**維持官方原本的樣子**（不染色）；要視覺提示的話，
戰鬥 › 準備 可以改成琥珀色或自訂顏色。

同一套東西也有命令列版本，適合看細節：

```powershell
npx tsx apps/companion/src/index.ts arbiter --port 9333 --phase-seconds 15
```

⚠ **這會改變遊戲行為**，而且有兩條路會送出 `I_am_ok`（準備放行、約定秒數）。
動手前先讀 [docs/arbiter-link.md](docs/arbiter-link.md) —— 裡面每一條「⚠」都是
實測踩過的失效模式。

#### 會改變勝負的功能都是「雙方同意才生效」

| 功能     | 協商 | 沒配到對手時         |
| -------- | ---- | -------------------- |
| 準備     | and  | 退回「誤按反悔」窗口 |
| 秒數上限 | max  | 完全不縮短           |
| 加速     | min  | 原速                 |

⚠ **加速引擎做好了，但 UI 刻意不開放。** 它改的是對戰的節奏，而節奏直接關係到
誰有多少時間思考；實測收益只有約 **1 分鐘／場**（伺服器排程那段動不了），
判斷錯的代價卻是公平性 —— 這個比例不值得先開放再修。設定頁那一格是前瞻預告。

#### 插件當掉時，遊戲會回到原本的樣子

| 注入的東西    | 插件當掉                     | 靠什麼               |
| ------------- | ---------------------------- | -------------------- |
| 準備（攔 OK） | **這個階段撐完，下一回取消** | 心跳 3 秒 → 降級模式 |
| 加速          | 10 秒內自己還原成原速        | 租約                 |

⚠ 準備那條刻意**不當場取消**。舊行為是心跳一過期就把壓著的 `I_am_ok` 送出去 ——
玩家剛按下 OK、以為「再按一次就取消」，那次按壓卻在他不知情時定案了。現在改成
頁面自己接手單邊的部分（再按一次仍可取消、剩 3 秒自己送出），到**下一個階段**
才真的關掉。開關只在階段邊界改變，永遠不會在玩家操作到一半時變。

不對稱是刻意的：**開啟隨時生效，關閉只在階段邊界** —— 關閉有傷害，開啟沒有。

## 核心概念：規則的身分是它的 Hash

一份規則的識別不是名字也不是版本號，是**內容的 SHA-256**。

```
規則 JSON → Schema 驗證 → Canonical JSON → SHA-256 → contentHash
```

因為「同樣叫 1.2.0 但內容被人改過」的兩份規則必須被判定為不同，否則
Room 一致性檢查就是假的。正規化採 **RFC 8785 (JCS)**，規格書 §5.2 要求的
四件事（鍵值排序、UTF-8、消除非語義空白、統一數值表示）正是它的定義。

```ts
import { contentHash, validateCostRule } from "@ulr/rule-schema";

const result = validateCostRule(json);
if (result.valid) {
  console.log(contentHash(result.rule)); // sha256:bebd49f8…
}
```

⚠ **ULGG 端（PHP）要實作同一套正規化，先讀 [docs/canonical-json.md](docs/canonical-json.md)。**
`json_encode(21.0)` 在 PHP 給 `21.0`、JCS 要求 `21`，這一個差異就會讓兩邊
所有 Hash 全部對不起來。`packages/rule-schema/test-vectors/canonical.json`
是語言無關的驗收向量，照著跑就對得上。

## 這個插件會連到哪裡、送什麼

**只有兩個對外連線**，兩個都到同一台伺服器（Cloudflare Workers，原始碼在
[`apps/link-worker`](apps/link-worker)）：

| 連線     | 何時           | 送出去的東西                        |
| -------- | -------------- | ----------------------------------- |
| 中間人   | **對戰中才連** | 雜湊過的場次編號 + 你的四個偏好設定 |
| 檢查更新 | 每小時一次     | 什麼都不送，只問「最新版是哪一版」  |

**不會送出去的東西**：你的名字、Steam 帳號或 token、對手是誰、任何一張手牌
或牌組內容、對戰結果。

場次編號是遊戲那個 32 字元 room id 的 **SHA-256 前 64 bit**（`roomKey()`）。
伺服器要回答的問題只有一個 ——「**這兩條連線在不在同一場對戰**」—— 而雜湊
足以回答它。所以「伺服器看得到什麼」是**數學問題，不是信任問題**：它認不出
那是哪一場，也認不出你是誰。

⚠ 沒進對戰時**完全不連線**。中間人連不上時自動退回單邊模式 —— 功能會少
（秒數不縮短、準備功能退回「誤按反悔」窗口），但不會壞。

自己架一台也可以：`apps/link-worker` 是完整的，把配置裡的「中間人」指過去就好。

## 給內測者

**目前是內測階段**，發布來源已經上線，插件會自己更新（每小時檢查一次，
**下載完不會在對戰中套用**）。

裝之前先知道三件事：

1. **Windows 會跳「不明的發行者」。** 安裝檔還沒有程式碼簽章（憑證要錢，
   內測階段先不買）。點「其他資訊 → 仍要執行」。不放心的話原始碼全部在這裡，
   自己 `npm run dist` 打包出來的是同一份東西。
2. **要先在 Steam 設一次 debug port**，否則插件永遠接不上（畫面只會寫
   「等遊戲…」）。步驟寫在插件的 **設置 › 連線** 那一頁，照著做一次就好。
3. **它會改變勝負。** 準備功能與秒數上限都是**雙方都裝了才生效**的東西，
   而且協商永遠取「對雙方都不更嚴格」的那一邊 —— 沒有任何設定能單方面
   縮短對手的思考時間。詳見下面的公平性立場。

回報問題時請附上**版本號**（視窗左上角那個 `v0.2.0`）與 **設置 › 記錄**
那一頁的內容 —— 那裡面不含任何遊戲內容，可以直接貼。

## 公平性立場

這個插件只改**自己客戶端的顯示**，伺服器收到的東西一個字都沒變。

- 不修改伺服器端技能判定，不繞過官方戰鬥規則
- 自訂 COST 是**自我約束**：雙方同意才有意義，亞城／官方環境完全不受影響
- 不顯示也不上傳對手未揭露的手牌、牌組或任何隱藏資訊
- 對局限制條款（`restrictions`）只顯示給人看，引擎不強制、也不解析條件字串

詳見規格書 §12。任何 PR 若違反上述任一條，不會被合併。
