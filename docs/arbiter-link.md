# 中間人握手與約定秒數（WP-15）

第一版只有兩個功能（玩家定的）：

| 功能             | 一句話                                                     |
| ---------------- | ---------------------------------------------------------- |
| **準備按鈕**     | 雙方都按了 OK 才真的送出 —— 先按的人不再被懲罰             |
| **準備時間縮減** | 雙方各設一個「移動階段要多長」，取**比較長**的那個當共同值 |

聖水／聖杯碰上麻痺時再提早 5 秒，那是第二項的一個修正項，不是第三個功能。

> ⚠ **這兩個功能都會改變勝負。** 底下每一條「⚠」都是實測踩過或推導出來的
> 失效模式，不是防禦性寫作。

| ---------------------------------------------------------------------- | ------ | ------------------------------------ |
| [`arbiter-link/protocol.ts`](../packages/arbiter-link/src/protocol.ts) | 兩邊   | 訊息、協商規則、房號雜湊（**純**）   |
| [`arbiter-link/rooms.ts`](../packages/arbiter-link/src/rooms.ts)       | 中間人 | 配對與合成訊號（**純**）             |
| [`arbiter-link/broker.ts`](../packages/arbiter-link/src/broker.ts)     | 中間人 | WebSocket 膠水，只聽 127.0.0.1       |
| [`arbiter-link/node.ts`](../packages/arbiter-link/src/node.ts)         | 插件   | 先搶著當中間人，佔不到就當客戶端     |

**換成 ulgg 的雲端版時只有 `broker.ts` 會被丟掉**，客戶端只換一個 URL。
Durable Objects 本來就講 WebSocket，一個 DO 實例 = 一間房，房號就是
`roomKey()`。ulgg 作者還沒回覆網站支不支援 WebSocket，但這個形狀對兩種答案
都成立。

## 三條紅線

### 1. 中間人**從不**單獨告訴任何一方「對手準備好了」

只有兩邊都好的那一瞬間才發一則 `both-ready`。協定裡**根本沒有**一則
「對手準備好了」可以發。

原本這條性質是伺服器保證的（`constants.ts` 的 `OK_STATE_EVENTS`：`I_am_ok`
只送不收，整場 90 次全是送出）。接了側通道之後它降級成**我們的設計選擇**，
所以 `rooms.test.ts` 有一條測試專門把它釘住。

### 2. 協商一律取「對雙方都不更嚴格」的那一邊

| 項目                   | 取法  | 為什麼                     |
| ---------------------- | ----- | -------------------------- |
| `phaseSeconds`         | `max` | 我選 10、對方選 15 → 用 15 |
| `hazardShortenSeconds` | `min` | 一方關掉這條，共同值就是 0 |
| `readyEnabled`         | `and` | 同步釋放要兩邊都參與才成立 |

⚠ **不要改成「我方優先」。** 這個功能存在的理由就是消除「先承諾的人被懲罰」
的不對稱；讓任何一方能單方面砍掉對手的思考時間，等於把不對稱換個方向裝回去。

### 3. 房號永遠是雜湊過的

`MainA.room` 是 32 字元的高熵字串（§12 的 `VALUE_MAX_STRING_LENGTH = 24`
正是為了擋這類東西）。中間人只需要回答「這兩個人在不在同一場」，那用
SHA-256 前 64 bit 就夠。之後接雲端伺服器時，「伺服器看得到什麼」是數學問題
不是信任問題。

> ✅ **順帶回答了 `battle-features.md` 的 probe 第 4 題**（match id 可不可
> 觀測）。2026-08-06 雙開實測：同一場對戰兩個客戶端的 `MainA.room` 完全相同。

## 準備功能：插件當掉時**不要當場取消**

`patch-ok` 一直有心跳（`DEFAULT_STALE_MS` = 3 秒），因為壓著 `I_am_ok` 不放會害
玩家棄權。但舊的反應是「心跳一過期就 `release("node-gone")`」，而那本身是一個
安靜的傷害：

> 玩家按下 OK、看到按鈕變色、以為「再按一次就取消」—— 就在這時插件當掉。
> 那次按壓在他完全不知情的狀況下**定案了**，畫面上什麼都沒說。

現在改成**這個階段撐完**。判準從 `hold && nodeAlive()` 換成 `holdThisPhase`，
它在**進入移動階段的那一刻**定案：

| 事件                     | 何時生效     | 為什麼                                 |
| ------------------------ | ------------ | -------------------------------------- |
| 玩家在托盤開／關（活著） | 立刻         | 有人明確下的令，UI 同步反映得出來      |
| 心跳過期（沒人下令）     | **下一階段** | 玩家不知情，當場改變會讓他以為還能反悔 |
| 心跳恢復                 | 立刻         | 只是多拿到一個反悔窗口，**沒有傷害**   |

⚠ **開啟隨時生效、關閉只在階段邊界** —— 這個不對稱是刻意的。少了「開啟隨時
生效」那條，「對戰中途才接上插件」會整個階段都沒有準備功能，因為第一輪
`phaseTick` 跑在 Node 的第一次 `tick()` 之前。

### 降級模式的安全網

Node 死了就沒有人會下釋放指令，所以頁面自己顧硬底線：剩
`localDeadlineSeconds`（3 秒，跟 Node 的 `DEFAULT_DEADLINE_SECONDS` 同值）就送出。

⚠ **`failsafeMs` 不夠用**：它是從「按下去」算起的 25 秒，不是從階段剩餘秒數算起。
玩家在階段剩 8 秒時才按的話，失效保護會落在階段結束**之後** —— 也就是逾時棄權。

⚠ 讀不到剩餘秒數（`remaining()` 回 null）就**立刻送出**。沒有安全網可言的時候
寧可早，不可以晚。

單邊的「誤按反悔」本來就不需要對手也不需要 Node —— 頁面自己做得到。
需要 Node 的只有「等對手也好了才一起送」，而那個在降級模式下本來就沒了。

## OK 鈕的染色：預設不動遊戲畫面

`readyTint` 預設 `null` = **不染色，維持官方原本的樣子**（玩家指定）。
可選琥珀色（`READY_TINT_AMBER`，跟系統匣圖示同一個值）或自訂顏色。

⚠ 染色原本的用途是「這個階段插件真的有在管」的視覺證明。預設關掉之後就沒有
這個訊號了 —— 所以**系統匣圖示的三色語意變得更重要**，不要為了「畫面乾淨」
也把它拿掉。

⚠ 換顏色走 `adapter.setReadyTint()`，**不要重裝 patch**。重裝會先把正壓著的
`I_am_ok` 送出去 —— 玩家只是在設定裡挑了個顏色，卻讓他這回合的 OK 定案了。

⚠ 壞掉的顏色值一律當成「不染色」，**不要夾成 `0x000000`** —— 那會把 OK 鈕染成
全黑，看起來像遊戲壞了，而玩家完全不會聯想到是自己填錯了一個顏色。

## 加速：本機的東西，為什麼要協商

> ⚠ **2026-08-08：引擎與協商都完成並實跑驗證過，但 UI 刻意不開放。**
> 它改的是對戰節奏，而節奏直接關係到誰有多少時間思考。實測收益只有約
> 1 分鐘／場，判斷錯的代價卻是公平性 —— 這個比例不值得先開放再修。
> 托盤的「戰鬥 › 加速」是前瞻預告，沒有開關。

`patch-speed` 只加快**自己畫面上**的亮牌與出牌卡頓，對手看到的一個像素都沒變。
看起來像純本機偏好 —— 但它會**提早把決策窗還給我**（`docs/battle-preplay.md`：
防禦階段預算只有 1.94s，光亮牌就吃掉 800ms），對手沒開就沒有那塊。

那是單方面拿到的時間優勢，跟 `phaseSeconds` 同一類問題，所以走同一條路：
`negotiate` 取 **min**，`soloSettings` 一律 1（原速）。

⚠ 舊版對手的 `hello` 不帶 `speedFactor`，`normalizePrefs` 補成 1 → min 算出 1
→ **加速自動失效**。缺欄位往「關掉」的方向壞，不是往「打開」。

### ⚠⚠ 插件當掉時，加速要自己還原

`patch-ok` 早就有心跳（`DEFAULT_STALE_MS` = 3 秒），因為壓著 `I_am_ok` 不放是
會害玩家棄權的。加速原本**沒有**同一道機制，而那留下一個安靜的錯誤狀態：

> 插件當掉 → 頁面上的 `setInterval` 還在跑（它跑在**遊戲的頁面裡**，不是插件
> 裡）→ 加速一直留著，直到玩家自己重載遊戲，而且沒有任何 UI 講得出這件事。

後果不只是「功能沒關掉」。加速是**協商出來的**，插件死掉之後那個協商已經不
存在了 —— 對手可能已經斷線、可能已經改成 1×，而我這邊還在享受提早拿回決策窗
的好處。那正是取 min 要防的事。

所以加了**租約**（`DEFAULT_SPEED_LEASE_MS` = 10 秒）：

| 誰                     | 做什麼                                                               |
| ---------------------- | -------------------------------------------------------------------- |
| 頁面                   | 每輪（200ms）先看 `Date.now() > expiresAt`，過期就自己 `uninstall()` |
| Node                   | 每 `SPEED_RENEW_MS`（≈3.3 秒）續一次約                               |
| 續約回 `not-installed` | 代表頁面那份不見了（多半是重載過）→ 重裝                             |

比 `patch-ok` 的 3 秒寬鬆，是因為兩邊過期的代價不同：這裡是「少加速幾秒」，
那裡是「玩家被鎖住」。抖一下就把功能關掉反而更擾人。

### 為什麼不是「每回合注入一次」

場景每個階段都會換新物件（`MovePhaseA` → `AttackPhaseA` → `MainA`），
`timeScale` 得**持續補**，所以是 200ms 的補套迴圈而不是一次性注入。
一回合只跑一次的話，換到下一個階段就失效了。

拆除有三條路，全部都會把 `timeScale` 還原成 1：正常關閉（`engine.stop()`）、
連線斷掉後重連時重裝、以及上面那條租約。

## 約定秒數：它跟硬底線是兩件事

|                   | 誰決定的     | 沒按 OK 也會送嗎 | 為什麼存在       |
| ----------------- | ------------ | ---------------- | ---------------- |
| `deadlineSeconds` | 本機，寫死   | ❌ 只有壓著才送  | 不讓玩家逾時棄權 |
| `capSeconds`      | **雙方協商** | ✅ **會**        | 縮短整個移動階段 |

**硬底線永遠排在約定秒數前面**（`arbitration.ts` 的 `tick` 分支）：一條是
安全機制，另一條是便利機制。

### 沒配到對手時秒數**一定要退回滿版 30 秒**

`soloSettings()` 在三個地方生效：房裡只有我、對手離線、側通道斷線。

⚠ 這不是保守，是算術：對手沒插件的話他照樣想滿 30 秒，我方照 15 秒送出
**只有自己提早承諾**。單方面縮短是純粹的自損。

### 玩家沒按 OK 時要**替他按一次 OK 鈕**，不要自己組封包

```js
// 遊戲自己的 pointerdown handler（2026-08-06 實測挖出來的）
() => { this.ok.setTexture("ok", 2).disableInteractive(),
        this.socket.emit(<OK 事件名>, this.room, this.id) }
```

`sc.ok.emit("pointerdown")` 會直接叫它 —— Phaser 的 GameObject 就是
EventEmitter，**不管物件可不可按**。好處有兩個：

1. 不變量 3 保住了：插件永遠不需要知道 `I_am_ok` 的協定長什麼樣
2. 送出後的按鈕外觀（frame 2 + 不可按）連帶對了，不必自己收拾

⚠ **必須有一個 pass-through 旗標**，否則遊戲 emit 出來的 `I_am_ok` 會撞到
我們自己的攔截 ——「強制送出」變成「強制壓住」，方向剛好相反。

### `committed` 與 `sent` 是兩個旗標，缺一不可

- `committed` **送出即清**：不清的話玩家的第二次按下會被忽略，那次呼叫壓到
  失效保護才送出而且取消不了（WP-12 的坑 #5）
- `sent` **換階段才清**：約定秒數那條路不看 `ready`，`committed` 一清它就會
  每 250ms 再「強制結束」一次

## 讀秒顯示：約定 15 秒就要**看起來**只有 15 秒

玩家要求。遊戲的倒數整段都是客戶端算的（實測原始碼）：

```js
this.timelimit = 30;                                      // create()
this.time.addEvent({ delay: 100, ... this.timelimit -= .1 })
// update() 每一幀從 timelimit 重算三樣東西：
text.setText(timelimit.toPrecision(...))
colorIdx = trunc(timelimit / 30 * 240)      // 240=藍 0=紅
guage.scaleX = timelimit / 30 * .934 + .066
```

三樣東西**全部是 `timelimit` 的純函式**，分母寫死 30。所以只要在 `update()`
之後用 `(timelimit − (30 − cap)) / cap` 重算同樣三樣，數字與讀秒條就一起對了。

⚠ **不要去改 `this.timelimit` 本身。** 硬底線、hazard、失效保護全部讀它。
改了它等於同時改掉三個安全機制，而症狀是「插件在還有很多時間的時候就送出」。
`state.remaining()` 因此改成直接讀 `timelimit`，不再解析畫面上的字 ——
那個字現在是我們自己寫的。

### ⚠⚠ 只換原型完全沒有效果（2026-08-06 對著真遊戲踩到）

Phaser 的 `Systems.init` 就把 `scene.update` **抄了一份**：

```js
if (this.scene.update) this.sceneUpdate = this.scene.update; // init
this.sceneUpdate.call(this.scene, time, delta); // 每一幀
```

場景建立**之後**才換原型，跑的還是舊的那份。症狀極度誤導：
`Object.getPrototypeOf(mp).update` 檢查起來是新版、`__ulrTimerPatched` 也是
true，**但畫面完全沒變** —— 看起來像我們算錯了，其實是根本沒被呼叫。

所以兩邊都要換：原型（之後 re-init 會抄到新版）＋ `sys.sceneUpdate`
（現在這一顆實例，立刻生效）。

> 這跟 `SOCKET_LIFETIME_NOTE` 是**同一個形狀的坑**：原型上的東西跨場活著，
> 實例上的抄本每場重來。這個專案裡已經有第二個了。
>
> 測試也照著修了：`patch-ok.test.ts` 的假場景現在有 `sys.sceneUpdate`，
> 而且 `frame()` 走它而不是直接叫 `update()`。原本的版本會讓「只換原型」的
> 實作測試全綠、實跑無效。

## 聖水 + 麻痺（`hazard`）

兩個條件同時成立才算，判斷**完全在頁面做，Node 只拿到一個布林**（§12）。

| 條件             | 資料來源                                                     |
| ---------------- | ------------------------------------------------------------ |
| 手牌有聖水／聖杯 | `event_info.frames[n].holy`（`n` = 手牌 sprite 的 frame 名） |
| 場上有麻痺等     | `state("mahi_2","A","B")` 事件，回合數自己數                 |

⚠ **JSON 的鍵是 `event_info` 不是 `event_asset`**，而且形狀是 `{ frames: [] }`
不是裸陣列。`event_asset` 是**材質**的鍵。實測索引：0=劍1卡、21=槍1卡、
42=防禦1卡、**91=聖水、94=聖杯卡、95=毒杯卡**。

⚠ **手牌要走 `MainA.arr1`，不要只看畫面上的物件。** 手牌會分頁
（`page` / `currentPage` / `arrow_left` / `arrow_right`），沒翻到的那頁在顯示
清單裡根本不存在 —— 漏掉的方向是「以為沒有聖水」，也就是這條規則安靜失效。

⚠ 伺服器**只在施加狀態時通知一次**，之後不再說還剩幾回合。所以要自己數：
每收到一次 `endTurn` 全部減一。中途接上插件的那一場算不出來 —— 那只會讓
hazard 判成 false（不縮短），方向是安全的。

> ⬜ **正向路徑還沒在真實對戰裡驗到。** 2026-08-06 那兩場沒有人拿到聖水，
> 也沒有人被麻痺。單元測試涵蓋了，但「真的看到 hazard=true」還沒發生過。

## 誰當中間人：玩家不需要知道這件事存在

每個插件都**先試著當中間人，佔不到就當客戶端**。誰先開誰當。

⚠ 當中間人的那個關掉之後，另一個要接手 —— 否則第一個玩家退出，第二個就
永遠停在 offline 而他什麼都沒做錯。所以斷線期間會一直重試搶那個埠。

## 托盤程式

```powershell
npm run tray                      # 開發預設：第一份**網頁版**配置
npm run tray -- --kind desktop    # 第一份桌面版配置
npm run tray -- --profile <id>    # 指定配置
npm run tray -- --port 59222       # 相容用法
```

兩份同時開，各管一個客戶端。托盤圖示的顏色**就是狀態**，跟遊戲裡 OK 鈕的
琥珀色同一套語意：

| 顏色 | 意思                                 |
| ---- | ------------------------------------ |
| 灰   | 連不上遊戲 —— 插件現在沒在管         |
| 琥珀 | 接上了，但還沒配到對手（秒數不縮短） |
| 綠   | 配對成功，約定秒數生效中             |

⚠ **不要把「已連線」畫成綠色。** 綠色必須留給「兩邊真的講好了」，因為那是
唯一會讓對手時間也被縮短的狀態。搞混的代價是玩家以為對手也被縮到 15 秒，
結果只有自己提早承諾。

### ⚠ 兩份 Electron 要能同時活著

1. `userData` 預設同一個目錄，兩個實例會搶同一份 cache → **依埠分開**
2. **刻意不用** `requestSingleInstanceLock()` —— 雙開正是預期用法

### 多開靠具名配置，不靠命令列

埠寫在命令列的話，一般玩家永遠開不了第二個。所以 `profiles.json` 存一張清單
（`apps/tray/src/profiles-core.ts` 是規則，`profiles.ts` 只做 I/O），設定頁按
「開新實例」就 spawn 一份帶 `--profile <id>` 的自己。

⚠ **`profiles.json` 不能放在 `userData` 底下** —— 那個路徑已經依埠分開了，
存進去的話每個實例都有自己的一份清單，「在 A 視窗新增的配置在 B 視窗看不到」。
放 `appData/ulr-companion/profiles.json`。

⚠ **每次寫入都先重讀再依 id 合併。** 兩個視窗本來就是預期用法，直接把記憶體
裡那份寫回去的話，B 視窗存檔會抹掉 A 視窗剛剛新增的配置。

三條會安靜壞掉的規則，都有測試釘住（`apps/tray/test/profiles-core.test.ts`）：

1. **新增時自動避開已佔用的埠** —— 撞到的話第二份根本開不起來（目錄鎖），
   而症狀是「按了開新實例但什麼都沒發生」
2. **最後一份刪不掉** —— 清單空了視窗沒有東西可綁，沒有 UI 救得回來
3. **`--port` 對不上任何配置時開臨時配置**，不是拒絕啟動

### ⚠ 開機啟動在開發模式下不能設

`process.execPath` 在開發時是 `node_modules` 裡的 electron.exe。把它寫進登錄檔
的話，之後開機會跳出一個空白的 Electron 視窗，而且很難聯想到是這裡設的。
`launch.ts` 用 `app.isPackaged` 擋掉，UI 也把那個開關停用並說明原因。

### ⚠⚠ `ELECTRON_RUN_AS_NODE`

VS Code 的 extension host 會設它，從那裡跑 npm script 會繼承。Electron 的 exe
於是被當成**純 Node** 執行，`require("electron")` 拿到的是只回傳路徑的殼：

```
TypeError: Cannot read properties of undefined (reading 'setPath')
```

錯訊完全看不出原因，唯一的線索是堆疊裡的 `node:electron/js2c/node_init`
（正常是 `browser_init`）。`scripts/run-tray.mjs` 存在的唯一理由就是把它拿掉。

> `constants.ts` 的 `ENV_KEYS_TO_STRIP` 早就為了「插件自己開遊戲」記過同一個
> 坑。2026-08-06 我們自己的 Electron 也踩了一次。

## 自動靜默更新

玩家要「不用管它」。照做，但有一條不能妥協的邊界：

> 下載可以完全靜默；**套用不能發生在對戰進行中。**

理由不是保守。`battle-features.md` 早就寫過：靜默把規則版本換掉等於在玩家
不知情時改變他對戰的行為，而且「昨天好好的今天壞了」排查會非常痛苦。
折衷是**版本換掉的那一刻要落在對戰之外**，而且留一行 log。

⚠ 還有一個獨立的理由：協定版本一變，中間人會回 `incompatible`，雙方當場
退回單邊模式。在移動階段中間發生的話，玩家會看到約定秒數突然消失而不知道
為什麼。

判準是 `status.armed`（攔截真的掛在 socket 上），**不是「有沒有連上遊戲」**
—— 連上但還在大廳是安全的套用時機，而那正是玩家最常停留的地方。

**沒有預設的發布來源**：`ULR_UPDATE_FEED` 沒設就整支不啟動。指向一個還不
存在的網址只會每小時失敗一次洗掉 log。清單要有 `sha256`，**沒有雜湊就不裝**
—— 下載回來的是會被執行的東西。
