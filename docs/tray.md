# 托盤程式（WP-15）

一份托盤程式管一個遊戲客戶端。畫面、多開、打包的細節都在這裡；
協定與仲裁的推導在 [arbiter-link.md](arbiter-link.md)，發布與自動更新在
[release.md](release.md)。

---

## 開發時怎麼開

```powershell
npm run tray                      # 開發預設：第一份 Chrome 配置
npm run tray -- --kind edge       # 第一份 Edge 配置
npm run tray -- --kind desktop    # 第一份桌面版配置
npm run tray -- --profile <id>    # 指定配置
npm run tray -- --port 59222      # 相容用法：對得上就用那份，對不上開臨時的
```

⚠ 不帶參數只在**開發時**是 Chrome（`scripts/run-tray.mjs` 補的），打包版仍然是
清單第一份。開發機上通常有一份安裝版正綁著桌面版 :59222 —— 開發版再去接同一個
埠會被單一實例鎖**安靜地擋掉**（看起來像「改的東西沒生效」）。

⚠ **對戰握手一律連 `ulr-link.lldavuull.workers.dev`**（見 README「會連到哪裡、送什麼」），
畫面上不給改，設定檔裡寫了別的也會被讀回來。要在同一台電腦上讓兩份插件互相握手
（雙開測試），啟動時帶 `--link local`（只活在那一次啟動，不落地）——
那時先開的那份會自動開本機轉送，不必再多開一個視窗。

⚠ **從 VS Code 的終端機啟動打包版會失敗**，錯訊是 `bad option: --port`。
那是 `ELECTRON_RUN_AS_NODE` —— VS Code 的 extension host 會設它，Electron 的 exe
於是被當成純 Node 跑。開發時用 `npm run tray`（`scripts/run-tray.mjs` 會清掉它），
或從捷徑／檔案總管開。一般玩家不會遇到。

同一套東西也有命令列版本，適合看細節：

```powershell
npx tsx apps/companion/src/index.ts arbiter --port 59222 --phase-seconds 15
```

⚠ **這會改變遊戲行為**，而且有兩條路會送出 `I_am_ok`（準備放行、約定秒數）。
動手前先讀 [arbiter-link.md](arbiter-link.md) —— 裡面每一條「⚠」都是實測踩過的
失效模式。

## 打包

```powershell
npm run dist        # → out/release/
```

發布物**只有 zip**（2026-09-14 起；NSIS 安裝檔發到 v2.0.0 為止）。理由與 zip 版的
自我更新見 [release.md](release.md)。用安裝器裝過的人一樣會收到 zip 更新，在原本的
安裝目錄換檔。圖示是程式現畫的漩渦，repo 裡沒有 `.ico`。

### 大小

zip 約 **116 MB**，解壓後 284 MB。這個大小幾乎全部是 Electron 自己：

|                            | 大小       |
| -------------------------- | ---------- |
| 我們的程式碼（`app.asar`） | **0.4 MB** |
| Chromium 主程式            | 200 MB     |
| GPU／著色器 DLL            | 42 MB      |
| ICU、授權條款、資源 pak    | 38 MB      |
| locale pak（5 種語言）     | 2.9 MB     |

已經做掉的：**locale 從 55 種砍到 5 種**（44 MB → 2.9 MB）、sourcemap 不進包、
`compression: maximum`。再往下就只剩 GPU 相關的 DLL，而砍掉它們的風險是
「某些機器上畫面靜靜地不出來」—— 對一個要在對戰中一直開著的工具不值得。

⚠ **Electron 的下限大約就是 70 MB**。真要做到 5–10 MB 得換成 Tauri／WebView2，
而那表示主程序要用 Rust 重寫 —— CDP adapter、仲裁引擎、中間人全部是 TypeScript，
不成比例。

### 程式碼簽章

⚠ **還沒有程式碼簽章**，zip 沒先「解除封鎖」就解壓的話，首次執行會跳 Windows
SmartScreen「不明的發行者」。後續更新不會再跳（更新是程式自己下載、換檔，不帶 Mark-of-the-Web）。
下載頁要老實揭露這件事並附 SHA-256，**不要教玩家關掉系統防護**。
zip 版「解除封鎖」那條路與簽章的行情分析在 [release.md](release.md) §5。

## 多開：具名配置

**多開是進階功能，預設關閉。** 一般玩家裝完就是一個視窗管一個遊戲客戶端，
不需要知道「配置」這回事 —— 要打開它得自己去 設置 › 關於 最底下勾「進階」，
「配置」才會出現在設置的**最後一格**（優先級最低）。

打開之後，設置 › 配置 維護一張清單，按「開新實例」就再開一個視窗綁另一份 ——
埠寫在命令列的話，一般玩家永遠開不了第二個。新增時會自動避開已被佔用的埠：

| 名稱   | 客戶端 | 遊戲埠 | 狀態     | 中間人   |
| ------ | ------ | ------ | -------- | -------- |
| 主帳號 | 桌面版 | 59222  | 對戰中   | （雲端） |
| 小號   | Chrome | 59223  | 遊戲開著 | （雲端） |
| 任務用 | Edge   | 59224  | 遊戲開著 | （雲端） |

⚠ **兩份配置不能共用同一個遊戲埠**（Windows 的目錄鎖會擋掉第二份，症狀是
「按了開新實例但什麼都沒發生」）。Chrome 與 Edge 各有自己的 profile 目錄與首選埠，
所以可以同時各掛一個帳號 —— 細節見 [launching.md](launching.md)。

「狀態」欄只說**那個埠上有沒有遊戲在回話**（主程序每四秒敲一次
`/json/version`）。**它回答不了「另一份有沒有插件在管它」** —— 那是另一個
process，這個視窗問不到。自己那一列才是引擎的真實狀態。

## 畫面

照里程碑分成九個大分頁，各自有側邊子分頁：

| 分頁     | 子分頁                                               | 狀態                        |
| -------- | ---------------------------------------------------- | --------------------------- |
| 戰鬥     | 準備 · 秒數上限                                      | ✅ 可用                     |
| 戰鬥     | 加速                                                 | 🟡 做好了，**刻意先不開放** |
| 戰鬥     | 記牌 · 牌譜                                          | 🔲 前瞻預告                 |
| 牌組     | 等候套用 · 雲端同步                                  | ✅ 可用                     |
| 牌組     | 牌組替換（插件模式／官方三牌組／關閉）               | 🟡 實機驗證中               |
| 渦       | 獎勵標記 · 結算通知                                  | ✅ 可用                     |
| 渦       | 物品捷徑                                             | 🟡 實機驗證中               |
| 渦       | 渦通報（說明頁，開關同互傳；見 `raid-feed.md`）      | 🟡 實機驗證中               |
| 迪特赫姆 | 隱藏地圖                                             | ✅ 可用                     |
| 迪特赫姆 | 物品捷徑 · GEM UP                                    | 🟡 實機驗證中               |
| 獎勵     | 物品捷徑                                             | 🟡 實機驗證中               |
| 任務     | 物品捷徑 · 寶箱標註                                  | 🟡 實機驗證中               |
| 模組     | 卡面替換                                             | ✅ 可用                     |
| 自訂COST | 對戰地點 · Cost 表 · 編輯 COST · 編輯規則 · 編輯描述 | ✅ 可用                     |
| 設置     | 連線 · 啟動 · 更新 · 記錄 · 關於 ·（進階）配置       | ✅ 可用                     |

2026-09-26 從牌組拆出兩個分頁：「自訂COST」（原本牌組底下的對戰地點～編輯描述）、
「迪特赫姆」（只在迪城有作用的東西；隱藏地圖從牌組搬過來）。

未實作的頁不是「敬請期待」—— 每一頁都寫清楚**卡在哪**。

牌組庫本身**不在托盤裡**：它畫在遊戲的牌組編輯畫面上（`patch-deck-edit.ts`），
托盤只多一格「等候套用」秒數。

卡面替換（模組 › 卡面替換）：玩家把 PNG 放進 `%APPDATA%\ulr-companion\mods\cards\`
（檔名 `史塔夏_R1.png` 或 `cc034_r01.png`），托盤盯著資料夾、`patch-card-art.ts`
把 `CharaCardImages` 圖集的那一格指到新圖（2026-09-23 改版前叫 `cc_front`），畫面上的官方卡面
（`circleMaskImage`）照官方遮罩參數重畫。空框是插件內建的（`apps/tray/assets/card-frames/`，
168×240 從 631 張卡統計、336×480 用 AI 放大，產生方式見 `scripts/extract-card-frames.ts`），
開機時複製到 `cards\空框\168x240\`、`336x480\`。

任務的兩頁都是開關（預設關）。物品捷徑跟渦房那個同一支腳本（`patch-item-panel.ts`）：
FRIENDLIST 正上方疊水與沙漏（水沙捷徑）、下方中間放通行證（通行證捷徑），兩塊各自開關。寶箱標註（`patch-quest-treasure.ts`）在
任務地圖每格旁邊畫官方卡面，內容表是原版 Unlight 開源碼的 TreasureDatas.csv
（`tools/build-quest-treasure.mjs` 產出 `quest-treasure-data.ts`）；「分配」格看目前牌組
COST 決定是哪一檔，不是隨機。Exp 格（OwnCard）畫牌頭同角色、等級 -1 的 L 卡（ULR 改過，
照玩家實測）；High Low 格標等級（Lv1～8），開始星數客戶端沒有表，進獎勵遊戲時記下
`bonus_data.step` 邊玩邊學，存在 `~/.ulr-companion/quest-bonus-learned.json`（`quest-bonus.ts`）。

迪特赫姆的物品捷徑與 GEM UP 也是 `patch-item-panel.ts`，只在 Match 場景、迪特赫姆頻道
畫：物品捷徑在 FRIENDLIST 正上方疊精靈／古代／魔女（預設關）；GEM UP 在右側、跟大廳同一個
位置畫 `PlayerBoostIcons` 的 `boost_1`＋倒數，上面標 `player_boost` 的加成百分比（預設開，
沒有 GEM 加成就不畫）。那張圖離開大廳會被卸掉，腳本用自己的 key 從資產主機抓同一張。

獎勵的物品捷徑也是 `patch-item-panel.ts`，三選一（預設無捷徑）：獎勵遊戲（Bonus 場景）猜錯時
只畫一顆建議用的道具，一點就走場景自己的 `use_bonus_item`（跟物品欄選道具同一個請求）。
樣子是官方「使用物品」鈕（`bonus_item`）抹掉字的圓鈕，裡面放道具圖＋數量；畫在
**使用物品左上**（縮小、尾巴朝中心，跟四顆大鈕圍成一圈）或**直接蓋住使用物品**（按同一個地方
就用；沒有能用的道具時不蓋）。配置是 `bonusItemShortcut`（開關）＋`bonusItemPlace`
（`above`／`cover`）。能不能用照官方 `can_use_bonus_item`（差距 ≤ 道具 value，value < 0 永遠
可以）；差距小時先用剛好夠的石楠1／石楠3，其餘照托盤選的優先順序（預設石楠5 → 四葉草 → 跳越星）。
取代原本預告的「未來視」。

畫面設定（解析度／畫面大小／全螢幕）同理：畫在遊戲 Option 的 plugin 分頁上
（`patch-display.ts`），托盤只負責記進配置的 `display` 欄。桌面版的全螢幕要
蓋住工作列得靠托盤用 Win32 推視窗（`window-fill.ts`），頁面自己做不到。

重新整理遊戲有兩個入口，**都不需要插件已經接上遊戲**（白畫面、斷線、重載空檔照樣能用，
走 `reload-page.ts` 另開一條 CDP 對頂層頁面下 `Page.reload`）：系統匣選單的「重新整理遊戲」，
以及桌面版遊戲視窗標題列上、最小化左邊那顆 ⟳（`title-button.ts`）。那顆鈕是托盤自己的
小視窗，由常駐 PowerShell 追著遊戲視窗貼上去、底色從標題列取樣，遊戲畫面蓋不到它；
為什麼不用 owned window、為什麼不透明，見 `title-button-core.ts` 檔頭。網頁版不裝（瀏覽器有 F5）。
休眠恢復／解鎖螢幕後那個小視窗的 Chromium 會停止出畫面（變一塊深灰、按了沒反應），
所以這時候、以及它的畫面程序掛掉或沒回應時，整個視窗連同 helper 重開一份（`title-button.ts` 檔頭）。

外觀是**純 CSS 重現**的 Unlight 風格，色票量自跑著的客戶端
（分頁 `#622b2f`／hover `#873136`、底 `#1e2336`）。系統匣圖示是程式現畫的菱形
（深紅描邊＋狀態色）。設定視窗**不用任何遊戲圖檔** ——
這既是它能維持 `default-src 'none'` 的原因，也避免第三方插件看起來像官方出品。
（唯一的例外是卡面替換的空框底稿，那是給玩家用繪圖軟體開的檔案，不畫在視窗上。）

遊戲裡的 OK 鈕預設**維持官方原本的樣子**（不染色）；要視覺提示的話，
戰鬥 › 準備 可以改成琥珀色或自訂顏色。

## 會改變勝負的功能都是「雙方同意才生效」

| 功能     | 協商 | 沒配到對手時         |
| -------- | ---- | -------------------- |
| 準備     | and  | 退回「誤按反悔」窗口 |
| 秒數上限 | max  | 完全不縮短           |
| 加速     | min  | 原速                 |

⚠ **加速引擎做好了，但 UI 刻意不開放。** 它改的是對戰的節奏，而節奏直接關係到
誰有多少時間思考；實測收益只有約 **1 分鐘／場**（伺服器排程那段動不了），
判斷錯的代價卻是公平性 —— 這個比例不值得先開放再修。設定頁那一格是前瞻預告。

## 插件當掉時，遊戲會回到原本的樣子

| 注入的東西        | 插件當掉                     | 靠什麼               |
| ----------------- | ---------------------------- | -------------------- |
| 準備（攔 OK）     | **這個階段撐完，下一回取消** | 心跳 3 秒 → 降級模式 |
| 加速              | 10 秒內自己還原成原速        | 租約                 |
| 房間閘門（WP-19） | 最多等 8 秒就原樣放行        | 看門狗               |

⚠ 準備那條刻意**不當場取消**。舊行為是心跳一過期就把壓著的 `I_am_ok` 送出去 ——
玩家剛按下 OK、以為「再按一次就取消」，那次按壓卻在他不知情時定案了。現在改成
頁面自己接手單邊的部分（再按一次仍可取消、剩 3 秒自己送出），到**下一個階段**
才真的關掉。開關只在階段邊界改變，永遠不會在玩家操作到一半時變。

不對稱是刻意的：**開啟隨時生效，關閉只在階段邊界** —— 關閉有傷害，開啟沒有。
